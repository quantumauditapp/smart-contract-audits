### `CD-01` — Unauthorized Token Movement  *(Severity: Critical · Status: Unresolved)*

The _executeSwapAndLiquify function allows the contract to move tokens from arbitrary addresses using transferFrom without sufficient validation, potentially allowing unauthorized drainage of user funds.

**Recommendation:** Restrict the use of transferFrom to only authorized contract-controlled addresses and implement strict access controls on the swap execution logic.


### `CD-04` — Ignored Transfer Return Values  *(Severity: High · Status: Unresolved)*

The _executeSwapAndLiquify function ignores the boolean return value of ERC-20 transfers, which can lead to silent failures where tokens are not moved but the contract state updates as if they were.

**Recommendation:** Always check the return value of transfer and transferFrom calls, or use OpenZeppelin's SafeERC20 library to handle non-standard token implementations.


### `CD-03` — Locked ETH in Contract  *(Severity: Medium · Status: Unresolved)*

The contract includes a receive function that accepts ETH, but there is no mechanism to withdraw or utilize these funds, effectively locking any ETH sent to the contract address.

**Recommendation:** Implement a withdrawal function restricted to a multi-sig or DAO, or remove the receive function if ETH reception is not intended.


### `CD-02` — Rounding Errors via Division Before Multiplication  *(Severity: Low · Status: Unresolved)*

In _executeSwapAndLiquify and _transfer, division is performed before multiplication, which causes precision loss and can lead to incorrect fee calculations.

**Recommendation:** Reorder operations to perform multiplication before division to maintain precision.
